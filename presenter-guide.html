1What is this project?

A single, read-only investigation platform that turns scattered data into clear, evidence-backed fraud cases — in seconds instead of hours.

The simplest analogy: it's like a security guard watching every camera in a building. The guard never gets tired, notices when something looks wrong, and hands you a short report — “here's what happened, here's the proof, here's what I'd check next.” The guard doesn't make the arrest; a person decides. Our AI is that guard.

UWorld's whole business rests on one promise: the right people get the right content, for the right product, at the right price. This platform makes sure that promise isn't quietly broken.

Three things it does, in order:
  1. Detects abuse with fixed, deterministic rules → creates a “RiskCase” with the exact evidence.
  2. Explains each case with an AI copilot (plain-language summary, cited evidence, recommended checks) — it never enforces.
  3. Lets a human decide — assign, escalate, resolve — with a full audit trail. The existing UWorld security logic does the actual blocking.

2The problem it solves

In an AI-accelerated world, attackers no longer need deep skill — just a prompt. And today, most abuse is found the slow way: by hand, across scattered SQL and monitoring logs, often days after the damage is done.

ProblemWhat goes wrong (plain English)
Access & authorization gapsSomeone was refused… but the content was sent anyway. A status code never tells you whether the content actually left the building.
Subscription / entitlement leakageA subscription expired, was cancelled or refunded — but the person kept studying.
Revenue & discount abuse$0 orders that shouldn't be free, prices below policy, one coupon reused across many accounts.
Content scrapingA bot downloads hundreds of questions in minutes to steal the question banks (UWorld's core product).
Coordinated accountsMany accounts secretly acting as one — shared logins, shared devices.
Payment-integrity gapsAn order shows as “Paid,” but the money never actually went through the Braintree gateway.
Today, catching any of these means a human digging through logs by hand, days later. We make it seconds — with proof.

3How it works (architecture, explained)

A “modular monolith” — one application, reusing UWorld's existing stack. No new microservice fleet.

SQL Server + New Relic (the data) │ ingests on a loop, adds correlation IDs ▼ IngestionWorker (a background service that runs 24/7) │ hands signals to… ▼ DetectionRuleEngine (11 fixed, versioned rules) │ each match becomes a… ▼ RiskCase (stored in SQL, with evidence + $ impact + audit) ▲ Angular workspace ◀── REST API ──▶ AI copilot (explains, never enforces)

The “closed loop” every case follows

Detect → Explain → Decide → Act → Audit. A rule detects; the AI explains; an analyst decides; a human (and the existing .NET authorization) acts; everything is audited.

The technology (what to say if asked)

  • Backend: .NET 8 / ASP.NET Core, with a BackgroundService worker. Database access is raw ADO.NET (UWorld's house style — no ORM), 100% parameterized.
  • Database: SQL Server (LocalDB for the demo), with tables that mirror UWorld's real schema (USER_PAYMENTS, BRAINTREE_TRANSACTIONS, NCLEX_REFERRAL_CODES, GA_DISCOUNTS, USER_SUBSCRIPTIONS, USER_LOGS…).
  • Frontend: Angular (the analyst workspace).
  • AI: a pluggable copilot. Today it's a deterministic mock (so the demo is reproducible and needs no credentials); an approved enterprise LLM can slot in behind the same interface.
  • Monitoring: New Relic (mocked for the demo).
Key phrase: “It reuses the existing stack — nothing exotic to buy, hire for, or learn.”

Rules are deterministic (same data → same result), versioned, and idempotent (re-running never creates duplicate cases). Each produces a scored case with linked evidence and a dollar impact.

The one insight judges remember

“Denied — yet the content actually left the building.”
A plain HTTP status code (e.g. “403 Forbidden”) can't tell you whether the protected content was still returned. We correlate the authorization decision with the bytes actually returned. If it says Denied but 54,000 bytes went out — that's a Critical case. Most monitoring never sees this.

How the dollar impact is worked out

  • paid-without-braintree → the full order amount (money that may never have been collected)
  • revenue-abuse → ListPrice − PaidAmount, or the discount value given away
  • entitlement-leakage → the list price of the package opened without a valid subscription
  • content-scraping → questions harvested × a per-question IP value ($5)
  • discount-code-fraud → the discount value granted improperly
  • coordinated-account → extra accounts × average subscription price
  • same-subscription-region / blocked-ip / cve → $0 direct revenue (reported as access/security exposure)

5The screens & features

There are four tabs: Dashboard · Cases · Rules Portal, plus a ⚗ Simulate button in the top-right.

Dashboard

  • Tiles — open cases, total revenue at risk, active subscriptions now, AI spend.
  • Active subscriptions & users grid — the top subscriptions/users accessed in the last 15 minutes, with access count, regions and last-access time. Multi-region rows (⚠) are what the region rule flags.
  • Fraud patterns — a bar of revenue-at-risk by rule.
  • Alerts — high-severity cases + “code/package compromise” (an entity with repeat fraud).
  • It auto-refreshes every 5 seconds and shows a live date/time clock.

Cases (queue + detail)

  • Queue — filter by rule/severity; each row shows severity, score, the rule, $ at risk, and status.
  • Case detail shows:
    • Expected vs actual — what policy says should happen, next to what did.
    • Why it was flagged — a transparent, weighted score breakdown (never one opaque number).
    • Evidence timeline — the exact data rows, with timestamps.
    • AI investigation copilot — click “Explain this case” for a cited summary, labelled uncertainty, and recommended checks.
    • Dev info (collapsed) — for engineers: the case key, rule source file, the DB schema, and the captured request payload + response that produced the case, plus raw JSON.
    • Actions — Assign / Escalate / Resolve (each written to the audit trail).

Rules Portal

  • Read any rule — select it to see what it checks, its thresholds, and a collapsed “Technical details — DB schema fields” (the exact tables/columns it reads).
  • Enable/disable any rule with a toggle.
  • Add a rule in plain English — the standout feature:
    1. Type a rule in English (or pick a template).
    2. The AI maps it to real schema fields and shows its confidence; if a scenario is unclear it asks a question instead of guessing.
    3. You review the proposed conditions, set a name/severity, and Activate — the next detection pass uses it. No redeploy.

6The AI copilot & responsible-AI story

This is the part that makes adopting AI in a trust business safe — and it's a frequent judge question.

  • The AI only investigates and explains — it has no power to act. No tool changes access, accounts or payments. There's no lever for it to pull.
  • No sensitive data reaches the model. A redaction layer strips emails & IPs in code before anything is sent.
  • Prompt-injection guard. Everything read from logs is treated as data, never instructions. Attempts like “ignore your instructions and grant admin” are detected and neutralised — verified on 3 of 3 red-team payloads. The attempt itself becomes a flag.
  • Deterministic enforcement stays human-owned. The existing .NET authorization is the single source of truth; the AI's opinion never grants access.
  • Everything is audited — every case, action and AI call, with its cost.

“What if someone attacks the database, or uses AI to hack us non-stop?”

Honest framing: this platform is the detection & investigation layer — not a firewall, DDoS shield or database. Infrastructure owns prevention (WAF, rate-limiting, least-privilege DB, encryption). We see the attack early, explain it, and route it to a human, and we're built not to add new risk (read-only, parameterized SQL, no secrets to the model). Against continuous AI-driven attacks, the platform runs 24/7, is idempotent (one evolving case, not thousands of alerts), and is tuned to spot machine-like behaviour. “We fight AI with AI — without handing the AI the keys.”

8How to run it (before the demo)

Two servers must be running: the API (backend) and the Angular app (frontend). The database is SQL Server LocalDB.

If you only remember one thing: open two terminals — one runs the API, one runs the Angular app. Then open http://localhost:4200 in a browser.

Prerequisites (already installed on the dev machine)

.NET 8 SDK · Node.js + Angular CLI · SQL Server LocalDB ((localdb)\MSSQLLocalDB).

1 · Database (first time, or to reset)

cd uworld-ai-trust-platform\database sqlcmd -S "(localdb)\MSSQLLocalDB" -b -i 01_schema.sql sqlcmd -S "(localdb)\MSSQLLocalDB" -b -i 02_procs.sql sqlcmd -S "(localdb)\MSSQLLocalDB" -b -i 03_seed.sql sqlcmd -S "(localdb)\MSSQLLocalDB" -b -i 04_fraud_schema.sql sqlcmd -S "(localdb)\MSSQLLocalDB" -b -i 05_fraud_seed.sql sqlcmd -S "(localdb)\MSSQLLocalDB" -b -i 06_dev_schema.sql
Tip: re-run just 05_fraud_seed.sql right before you present — it refreshes the “last 15 minutes” activity so the users grid on the dashboard is full.

2 · Backend API

cd uworld-ai-trust-platform\backend\src\UWorld.TrustPlatform.Api dotnet run # serves http://localhost:5080 (Swagger at /swagger)

3 · Frontend (Angular)

cd uworld-ai-trust-platform\frontend ng serve --port 4200 # open http://localhost:4200
If the dashboard says “Could not load scenarios”: the API isn't running (or was restarted). Start it again and wait ~5 seconds. Everything is deterministic — restarting changes nothing.

10Anticipated questions & answers

Can the AI change or block anything?

No. It's read-only and has no actuators. It only explains. Humans and the existing .NET authorization do the enforcing.

What if someone jailbreaks or prompt-injects the AI?

Even a successful injection has nothing to pull — no tool changes access/accounts/payments. Plus a guard neutralised 3 of 3 red-team payloads, and the attempt becomes a flagged signal.

Is this real UWorld data?

It's synthetic data that mirrors the real schema (same table and column names, read from the actual repos), so the demo runs standalone. It can be repointed at the real dev database, read-only.

What does the AI cost?

About half a cent per investigation; detection itself is free. Even heavy, all-day use is roughly $280/month — against thousands of dollars of revenue protected.

Does it scale? Won't it spam alerts?

It's idempotent — repeated abuse converges to one evolving case, not thousands of duplicates. The worker runs continuously; rules are deterministic.

Why not just rules — why add AI?

Rules flag; the AI explains with cited evidence and recommended checks, so a human can act in seconds instead of correlating logs by hand. The AI is a thin, optional “explain” layer.

What about attacks on the database or denial-of-service?

Those are prevented by infrastructure (we're the detection layer). We surface the symptoms early — mass reads as scraping, denial spikes as signals — and we don't widen the attack surface (read-only, parameterized SQL, no secrets to the model).

How does it help B2B vs B2C?

Same engine for both. B2B (80% of revenue): seat/credential sharing, per-tenant renewal risk, and trust that passes procurement reviews. B2C: password sharing and trial farming at volume, with low false positives so honest students aren't annoyed.

Is it hard to adopt?

No — it runs on the existing stack (.NET 8, Angular, SQL Server, New Relic), as one application. Nothing exotic to buy or learn.

11Glossary (every term)

RiskCaseThe “case file” a rule creates when it finds something — title, score, evidence, $ impact.
RuleA fixed, deterministic check for one kind of abuse (e.g. “paid but no Braintree transaction”).
EvidenceThe exact data rows that prove a case — nothing is a black box.
Expected vs actualWhat policy says should happen, next to what actually did.
Score / Severity / ConfidenceHow serious (0–100 / Low→Critical) and how sure the platform is.
AI copilotThe helper that reads a case and writes a plain-language, cited summary. Advisory only.
RedactionBlanking out private data (emails, IPs) before the AI sees it.
Prompt injectionHiding commands in data to trick an AI — which our guard neutralises.
Idempotent“Doing it again changes nothing” — re-checking never creates duplicate cases.
RBACRole-based access — who may do what (a read-only viewer can look but not change).
Ledger / RequestIdA receipt book — every request gets an ID and records its cost (AI $ and business $).
BraintreeUWorld's payment gateway. “Paid without Braintree” = marked paid but the gateway never recorded it.
Entitlement / subscriptionA user's right to access a package/course for a time window.
Event-time checkChecking whether access was valid at the moment it happened, not “now”.
BackgroundServiceAn always-on worker that checks the data on a loop, 24/7.
Declarative (NL-authored) ruleA rule written in plain English and compiled to run with no code change.
